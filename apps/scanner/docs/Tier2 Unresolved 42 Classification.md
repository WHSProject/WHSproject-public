# Tier2 미복원 42건 원인 분류

작성일: 2026-09-30. 관련 Issue: #403. 진단 구현: #401 / PR #402.

## 결론

미복원 42건을 재검사한 결과, 패키지 기준으로 **변환 미지원 23건, 동적 코드 미복원 13건, 문법·변환 오류 6건**으로 나뉘었다. 모두 시간 초과 때문에 실패한 것은 아니다. 새 복원 기능 확대보다 **기존 문자열 상수 치환의 정확성 문제를 먼저 수정**하는 것이 타당하다.

이번 작업은 진단과 분류이며 복원 기능을 수정하지 않았다. Tier2 전체의 효과, 최종 악성 판정 성능 또는 개선 후 복원율을 측정한 결과가 아니다.

## 대상과 실행 조건

- 원래 600건 실험에서 Scanner/Socket 결과가 함께 유효했던 580건 중, Tier2 대상으로 선정됐지만 Handoff가 없었던 42건을 선택했다.
- 악성 라벨 14개, 정상 라벨 28개 패키지다. 라벨은 데이터셋의 **패키지 단위** 라벨이며 개별 파일의 악성 여부를 보증하지 않는다.
- 진단 실행 커밋: `f815759150b08c76cc28f7c2ebc85bde469cafdb` (PR #402). PR #398의 복원 변경은 포함하지 않았다.
- 실행 이미지 ID: `sha256:116bf7e6f91ecb9be2be63996678da344d3702f34ce1af078bb9dacad9125e0c`.
- GuardDog 3.1.0 / Semgrep 1.172.0, 저장된 아카이브의 SHA-256 확인, 비루트·네트워크 차단·읽기 전용 Docker 정적 검사.
- 패키지/설치 스크립트 실행, Socket 재조회, 실제 LLM 호출은 모두 없었다. 원본 600건 결과를 덮어쓰지 않았다.
- 본 문서는 별도 최신 dev 기반 브랜치에서 작성했다. 문서 브랜치 자체가 진단 실행 소스라는 의미는 아니다.

GuardDog 사용 경로 42건은 모두 `COMPLETED`, 미사용 경로 42건은 모두 `PARTIAL`이었다. 후자는 GuardDog 검사를 의도적으로 생략한 상태다. 실행 실패 패키지는 0건이다. 이는 **정적 검사 실행 완료**이며 Tier2 복원 성공을 뜻하지 않는다.

## 1. 원인별 집계

주 분석은 기존 대상 선정 조건과 같은 GuardDog 사용 경로다.

| 최종 사유 | 악성 패키지 | 정상 패키지 | 패키지 합계 | 파일 수(악성/정상) | 고유 소스 해시 |
| --- | ---: | ---: | ---: | ---: | ---: |
| NO_SUPPORTED_TRANSFORM | 6 | 17 | 23 | 27 (6/21) | 27 |
| DYNAMIC_DECODE_UNRESOLVED | 6 | 7 | 13 | 15 (6/9) | 12 |
| PARSE_FAILED | 2 | 4 | 6 | 9 (4/5) | 8 |
| 합계 | 14 | 28 | 42 | 51 (16/35) | 47 |

이번 표본에서는 한 패키지의 파일들이 같은 최종 사유에 속하므로 패키지 수를 합산할 수 있다. 일반적으로는 파일마다 다른 사유가 생길 수 있으므로 사유별 패키지 수를 무조건 합산하면 안 된다.

- 42개 패키지에서 총 51개 파일이 선정됐다. 기존 결과의 파일 선정 수와 모두 일치했다.
- 복원 성공/부분 복원, Handoff 생성은 모두 0건이었다. 진단 추가만으로 복원 결과가 개선된 것은 아니다.
- 51개 파일 모두 STRUCTURE는 `SKIPPED / NOT_APPLICABLE`이었다. 따라서 이 표본을 webcrack 실패 사례로 설명하면 안 된다.
- 예산 초과 또는 TOOL_TIMEOUT은 관측되지 않았다. 파일 처리 시간은 중앙값 19ms, p95 310ms, 최대 1,300ms였다. 단일 실행 실측이고 파일 전체 처리 시간이며, Docker/Tier1 실행 시간을 포함하지 않는다.
- Tier1 analyzer의 보고된 errorCount는 모두 0이었다.

## 2. 변환 미지원: 23패키지 / 27파일

이 분류는 복원기가 의미 있는 변환을 적용하지 못했고 잔존 DYNAMIC_EVAL도 없었다는 뜻이다. “악성 난독화를 놓쳤다”와 같은 의미가 아니다.

27개 파일의 관측 신호는 CHAR_CODE / ESCAPED_LITERAL 범위였다. 이 신호는 정상 파서·정규식·문자 처리에도 나타난다.

실제 소스를 텍스트로 확인한 예:

- `xmldom@0.6.0 / lib/sax.js`: XML 이름의 유니코드 범위를 검사하는 정규식과 문자 코드 처리가 있다.
- `secure-json-parse@3.0.1 / index.js`: 이스케이프 표현까지 검사하는 정규식이 있다.

이 예시는 정상 문자열 처리도 선정될 수 있음을 보여준다. 다만 27개 파일 전체를 정상 코드로 확정한 것은 아니다. 특히 악성 라벨 패키지의 특정 파일이 이 분류에 들어갔다고 패키지 전체를 정상으로 처리해서는 안 된다.

후속 후보는 신호의 존재와 **실제로 정적 변환이 가능한지**를 구분하는 선정 품질 평가다. 지금 임계치를 일괄 낮추거나 해당 신호를 삭제할 근거는 부족하다.

## 3. 동적 코드 미복원: 13패키지 / 15파일

의미 있는 변환이 적용되지 않았고 DYNAMIC_EVAL 신호가 남았다. 이 결과만으로 동적 코드가 악성인지, 정적으로 완전히 복원 가능한지 판단할 수 없다.

정상 라벨에서 직접 확인한 용도:

- `@protobufjs/inquire@1.1.0`: 계산된 require 접근을 통한 선택적 모듈 로딩.
- `ordered-binary@1.5.3`: new Function을 이용한 문자열 처리 함수 생성.
- `rollup-plugin-terser@7.0.2`: 전달받은 옵션 문자열 평가.

악성 라벨의 `tailwind-base-theme@1.0.0` 및 `cli-color-ext@4.3.9`에서 선정된 파일은 바이트 단위로 동일하다. 사용자 정의 문자열 디코더와 외부 응답에 의존하는 동적 코드가 함께 있었다. 일부 문자열의 정적 해석과 전체 런타임 동작 복원은 별개 과제다. 외부 코드를 내려받거나 실행해서 확인하지 않았다.

나머지 파일들의 세부 의미 유형은 미확정이다. `DYNAMIC_DECODE_UNRESOLVED` 15개 모두를 “같은 디코더 하나를 추가하면 해결되는 15개 사례”로 계산하지 않는다.

## 4. 문법·변환 오류: 6패키지 / 9파일

원본 파일을 실행하지 않고 `restoreStrings → normalizeCode → validateRestore`를 다시 적용했다. 구조 단계는 원래 모두 건너뛰었으므로 같은 문자열·정규화 경로를 조사할 수 있었다. 현재 PARSE_FAILED는 실제 파싱 오류뿐 아니라 AST 변환 예외도 포함하므로 세분화가 필요하다.

| 하위 원인 | 파일 수 | 관측 근거 |
| --- | ---: | --- |
| 원본 문법 유효, 문자열 치환 후 문법 무효 | 3 | msgpack-lite 1파일 및 esoftplay 두 버전의 동일 crypt.js. 문자열 단계 직후부터 postfix 연산의 좌변 오류 |
| 원본 문법 유효, 문자열 단계에서 AST 타입 오류 | 3 | chevrotain 2파일의 ExportSpecifier local, bowser 1파일의 ForInStatement left에 StringLiteral이 들어가는 예외 |
| 현재 파서 설정에서 원본부터 거부 | 3 | esoftplay 두 버전 CLI의 최상위 return, @vitest/expect의 중복 선언 |

### 우선 수정 대상: 문자열 상수 치환

첫 두 행은 총 6파일 / 5패키지 / 5고유 소스다. 악성 라벨 2패키지, 정상 라벨 3패키지에 걸쳐 나타났다. 단, esoftplay 패키지는 마지막 행에도 포함되므로 하위 유형의 패키지 수를 합산하지 않는다.

`string-restorer.ts`는 수집한 문자열 바인딩을 Identifier 방문 중 StringLiteral로 치환한다. 조사한 오류는 좌변·갱신 연산·export 식별자처럼 식별자 형태를 유지해야 하는 위치와 관련된다. msgpack-lite 사례는 기록된 문자열 변환이 CONST_INLINE뿐이었고 문자열 단계 직후 문법이 깨졌다.

따라서 다음 구현은 **읽기 위치와 바인딩/쓰기 위치를 구분해 문자열 치환을 제한하고, 무해한 최소 fixture로 회귀 검증**하는 범위가 적절하다. 이번 문서 작업에서는 수정하지 않았다. 6파일이 수정 후 반드시 복원되거나 악성 탐지로 이어진다는 보장은 없다.

### 따로 다뤄야 하는 원본 파싱 문제

- CommonJS 파일의 최상위 return은 현재 파서 설정과 실행 문맥의 차이를 먼저 검토해야 한다. 이를 곧바로 잘못된 패키지 문법으로 단정하지 않는다.
- @vitest/expect의 중복 선언은 사용한 아카이브의 원본 품질/배포 파일 구성을 추가 확인해야 한다. 상류의 모든 배포본에 동일 문제가 있다는 주장은 하지 않는다.
- 파서 검증을 느슨하게 바꾸거나 오류를 성공으로 숨기는 것은 해결책에 포함하지 않는다.

## 5. 중복과 비교 경로

51개 파일은 47개 고유 SHA-256이다. 다음 네 쌍이 각각 동일하다.

| 동일 소스 쌍 | 해석 |
| --- | --- |
| stacktrace-gps의 루트 파일 / dist 파일 | 같은 패키지 내 배포본 중복 |
| tailwind-base-theme의 log.js / cli-color-ext의 prepare-writer.js | 패키지 간 동일 코드 |
| esoftplay 두 버전의 modules/lib/crypt.js | 버전 간 동일 코드 |
| hashset-cpp 내 jquery-1.4.3.min.js / jquery.min.js | vendored 파일 중복 |

해시 중복 제거는 바이트 동일성만 의미한다. 해시가 다르더라도 같은 코드 계열일 수 있다.

GuardDog 미사용 비교에서는 34패키지 / 43파일이 선정됐고 사유는 변환 미지원 26파일, 동적 미복원 8파일, 문법·변환 오류 9파일이었다. 남은 8패키지는 선정되지 않았다. 미사용 경로에서 파일이 줄었다는 사실을 복원 성공 또는 오탐 개선으로 해석하지 않는다.

## 6. 권장 순서와 완료 기준

1. **기존 문자열 치환 정확성 수정**: postfix/대입 대상/for-in/export 등 무해한 회귀 fixture를 추가하고 원본이 유효하면 잘못된 AST를 생성하지 않음을 검증한다. 오류가 난 6파일을 다시 비교하되 복원 성공과 탐지 개선을 별도 집계한다.
2. **원본 파싱 문제 분리**: CommonJS 문맥과 아카이브 품질을 확인하고 변환 실패와 구분한다. 정책/스키마를 바꿔야 한다면 별도 합의를 거친다.
3. **선정 품질 평가**: 정상 정규식/문자 처리 표본을 대조군으로 삼아 불필요한 후보를 줄일 수 있는지 평가한다. 악성 라벨 및 기존 신호 보존도 함께 확인한다.
4. **제한된 정적 디코더 지원 검토**: 중복 제거한 동적 미복원 표본을 대상으로 한다. 외부 응답이나 런타임 의존 코드를 임의로 복원 성공 처리하지 않는다.

최우선 작업은 1번이다. 신규 기능 확대, Gate 변경, LLM 자동 호출, 전체 600건 재실행은 이번 결론에 자동으로 포함되지 않는다.

## 7. 검증과 원자료

로컬 Git 제외 경로 `reports/validation/`:

- `tier2-restore-diagnostics-42-manifest.json`: 대상 42건, 아카이브 해시, 기존 결과.
- `tier2-restore-diagnostics-42-rerun-2026-09-30.json`: 고정 커밋의 GuardDog 사용/미사용 84개 실행 결과.
- `tier2-restore-diagnostics-42-file-review-v2-2026-09-30.json`: 51개 파일 해시·상태·시간·신호 및 파싱 재검사 기록.
- 같은 이름의 v2 없는 file-review JSON은 중간 기록이며 위 v2를 최종 파일 분석 근거로 사용한다.

검증 완료:

- 두 경로의 대상 ID가 manifest 42건과 정확히 일치하며 누락/중복이 없음.
- 51개 파일 진단과 별도 파일 분석 결과의 path/status/reason/duration/stageResults 일치.
- 기존 대상 선정 파일 수와 일치, Handoff 0, 예산 초과 0, Tier1 analyzer errorCount 0 확인.
- 입력 아카이브 42개 해시 및 원본 600건 관련 JSON 3개 해시 보존 확인.
- 진단 구현의 Scanner 테스트 1,178개 통과는 PR #402에서 수행한 결과다. 이 문서 브랜치에서 새로 실행한 코드 테스트가 아니다.
- 결과 문서의 집계는 원본 JSON에서 대조했다. GitHub CI는 PR #402에서 계정 결제/사용 한도 문제로 시작되지 않았다. 로컬 검증을 원격 CI 통과로 표시하지 않는다.

재현 시 PR #402 커밋에서 Scanner를 빌드하고, 위 manifest를 OMC_SOURCE_REPORT, 별도 새 출력 경로를 OMC_PILOT_OUTPUT, 저장된 아카이브 디렉터리를 OMC_ARCHIVE_DIR, OMC_EXPECTED_CASES=42로 지정한다. OMC_EXTERNAL_IMAGE와 OMC_EXTERNAL_IMAGE_DIGEST에는 위에서 검증한 동일한 전체 이미지 ID를 지정한다. 이미 존재하는 결과를 덮어쓰지 않는다.

파일 수준 재검사는 정적 변환만 호출하며 샘플 코드를 eval/import/실행하지 않는다. 원본/문자열 변환 직후/정규화 후 각각 validateRestore의 parse 결과를 비교한다. 원자료는 제한된 로컬 실험 자료이므로 코드 본문이나 payload를 PR에 첨부하지 않는다.
