# Tier2 문자열 복원: 동작 보존과 유지보수

관련 작업: #413의 문자열 바인딩 수정 후속 검증. 기준 커밋은 `252447ef04968f6a319841ddff7111481c1649a7`이며 이 문서는 그 이후 로컬 변경을 설명한다.

## 목적과 변경 범위

문법이 유효한 복원본도 원본과 다르게 동작할 수 있다. 따라서 문자열 복원을 수정할 때 문법 검사뿐 아니라 **통제된 무해한 예제의 관찰 가능한 동작**을 비교한다. 실제 패키지의 실행 동등성을 증명하는 테스트는 아니다.

Scanner의 string-restorer, 관련 테스트 및 문서만 변경한다. API/Evidence/Decision Schema, Gate/Policy, Docker 실행 방식, 환경변수, 의존성을 변경하지 않는다. 테스트 실행 편의를 위해 `test:tier2:restore` 명령만 추가하며 기존 테스트 명령과 CI 설정은 유지한다. PR #398/#402의 변경을 병합하지 않는다.

## 수정한 조건

| 대상 | 이전 문제 | 현재 처리 |
| --- | --- | --- |
| Buffer | `Buffer.from()` 자체를 문자열로 치환해 타입·인덱싱·출력 인코딩 변경 | Base64/Hex 입력의 `Buffer.from(...).toString(...)` 전체 체인만 치환. 리터럴 출력 인코딩을 존중하고 범위·동적·추가 인자는 보존 |
| atob | Buffer의 관대한 파싱과 UTF-8 변환을 사용 | 내장 atob의 잘못된 입력 예외와 binary string 의미를 사용. 기존 디코딩 크기 제한 유지 |
| 디코더 이름 | 동명 파라미터·로컬 함수도 내장 함수로 취급 | 실제 바인딩이 있거나 with 내부이면 치환하지 않음 |
| 호출 인자 | 사용하지 않는 것처럼 보이는 추가 인자의 부수효과 삭제 | 지원하는 정확한 인자 개수만 치환. 문자열 toString은 인자가 없을 때만 제거 |
| 문자열 바인딩 | 초기화 전 읽기·함수 호출 순서를 무시 | 같은 함수·문장 목록에서 앞선 초기화만 인정. 한 변수 선언 내 선언자 순서도 확인. direct eval이 있으면 let/var 인라인 제외, with가 있으면 전체 상수 인라인 제외 |
| eval | 선언·strict directive가 외부 범위로 새어 나옴 | 호출 위치의 strict mode로 파싱. 단일 인자·문장 위치·비 shadowing 호출에서 선언/directive 없는 표현식 문장만 승격. 나머지는 기존 호출 유지 |
| 템플릿 | tagged template을 문자열로 바꿔 raw/cooked 인자 계약 파괴 | 태그가 있는 템플릿은 유지 |
| directive | 폴딩한 문자열이 새 use strict directive로 해석됨 | 실제 directive와 일반 문자열 문장을 구분하고 후자는 괄호로 유지 |

확실하지 않은 코드를 그대로 두면 복원 수가 감소할 수 있다. 이를 성공으로 강제 분류하거나 기존 실패를 숨기지 않는다. 파이프라인 테스트는 범위에 민감한 eval이 `UNRESOLVED / DYNAMIC_DECODE_UNRESOLVED`로 남는지도 확인한다.

## 반복 검증 방법

프로젝트 의존성이 설치된 Node 24 환경에서 실행한다.

```bash
cd apps/scanner
npm run test:tier2:restore
npm run typecheck
npm test -- --runInBand
npm run build
```

- 집중 검증은 문자열 바인딩, 동작 비교, 파이프라인, 라인 매핑 4개 suite를 실행한다.
- `string-restorer.semantics.spec.ts`의 저장소 작성 예제 42개는 원본의 기대 결과를 먼저 검사한 뒤 복원본·재복원본을 비교한다. 기록된 값, 호출 순서/부수효과, 예외 이름 및 복원본 문법을 확인한다.
- fixture의 `records`는 record 호출 인자 배열을 JSON으로 직렬화한 목록이다. 타입 차이를 검사하려면 `typeof`, `Buffer.isBuffer`, 문자 코드 등을 명시적으로 기록한다. 예외 메시지는 런타임 버전에 따라 달라질 수 있으므로 이름을 비교한다.
- `node:vm`은 보안 샌드박스가 아니다. 이 테스트에 패키지 파일·다운로드한 코드·사용자 입력을 연결하지 않는다. 저장소에서 검토한 무해한 예제만 실행하며 각 실행에 200ms 제한을 둔다.
- 새 수정에는 실패 재현 예제와 기대 동작을 추가한다. 기존 fixture의 기대값을 구현에 맞춰 바꾸지 않는다. 지원되는 정상 복원 경로와 미지원 경로를 함께 검사한다.

2026-09-30 로컬 최종 검증: 집중 검증 **4 suites / 79 tests**, Scanner 전체 **74 suites / 1,231 tests**, 타입 검사·빌드 통과. 이번에 추가한 테스트는 동작 비교 42개와 파이프라인 2개다. 테스트 개발 중 기록 함수의 반환값 때문에 잘못된 fixture 기대가 1개 발견되어 수정했고, eval 교체 후 분리된 Babel 경로 처리도 보완했다. 최종 결과에 미해결 테스트 실패는 없다.

## 기존 6파일 정적 재검사 — 2026-09-30

기존 아카이브·파일 SHA-256을 대조하고 실제 패키지를 실행하지 않은 채 현재 파이프라인을 적용했다. 5패키지 버전의 6파일이며 고유 파일 해시는 5개다.

| 파일 묶음 | 1차 바인딩 수정 | 이번 동작 보존 보강 |
| --- | --- | --- |
| msgpack-lite 1파일, chevrotain 2파일, bowser 1파일 | RESTORED 4 | RESTORED 4 |
| esoftplay 두 버전의 동일 crypt.js | PARTIAL_RESTORED 2 | UNRESOLVED 2 |
| 복원 파이프라인 출력 문법 오류 | 0 | 0 |

esoftplay는 보수적인 초기화·함수 경계 검사 후 의미 있는 STRING 변환이 없어져 `DYNAMIC_DECODE_UNRESOLVED`로 남았다. 이것은 새 악성 탐지나 복원율 상승이 아니라 **불확실한 치환을 중단한 결과**다. 두 파일의 문법은 유효하고 원본 해시도 유지됐다.

- 최종 정적 결과: `reports/validation/tier2-string-semantics-6-recheck-final-2026-09-30.json` (Git 제외).
- 검사 당시 string-restorer SHA-256: `f04b24eabf577fcfb6f2061e6805cf1c62c6c9115d6cccb097e19405c28254eb`.
- JSON의 baseCommit은 부모 커밋이며 실제 수정본은 위 소스 해시로 식별한다.
- 이번 정적 검사는 GuardDog/Custom Rule 재분석이나 Handoff 재측정을 포함하지 않는다. 이전 5패키지 pilot의 Handoff 5건·후보 증거 54건은 이전 코드의 결과로만 보존한다. 이번 코드의 성과로 재사용하지 않는다.
- 원본 600건 실험도 별도 버전의 측정이다. 최신 수치가 필요하면 먼저 코드를 고정하고 동일 manifest로 제한된 pilot을 재실행한다.

## 보장하지 않는 것

- 42개 예제 통과는 임의 JavaScript 전체의 의미 동등성 증명이 아니다. Webcrack 구조 복원, NORMALIZE 단계 전반, 비동기 실행 순서, 모든 예외/스택/성능 특성을 검증한 것도 아니다.
- 정적 디코딩은 표준 내장 함수/프로토타입이 변경되지 않았다는 전제가 있다. 전역 객체 재대입, monkey patch, Proxy/getter, indirect eval에 의한 변경 등은 일반적으로 추적하지 않는다.
- 함수 간 실행 순서 및 일반 제어 흐름 분석은 추가하지 않는다. 실제로 안전한 코드도 보수적으로 미복원될 수 있다.
- LLM, 네트워크/API, Docker, 패키지 설치 스크립트 실행 및 전체 600건 재실행은 이번 검증에 포함하지 않는다.
- 로컬 테스트 통과는 GitHub CI 통과와 다르다. 원격 CI 결과와 계정 실행 제한은 별도 확인한다.
