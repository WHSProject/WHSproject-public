# CFF 그룹 40파일: 원본 대조와 평가 분모 검증

검증일: 2026-10-05. 대상: 기존 로컬 JsDeObsBench 기반 `control-flow-flattening` 표본 40쌍.

## 1. 결론

**표기 변화만 있는 6건을 제외한 후보 선정률은 27/34 = 79.4%로 보고할 수 있다. 단, 34건은 순서표·switch 기반 평탄화 11건과 helper를 통한 연산·호출 우회 23건의 합계다.** 따라서 79.4%를 아무 설명 없이 “순수한 제어흐름 평탄화 탐지율”이라고 부르면 안 된다.

이번 작업은 탐지 코드 수정이 아니라 **평가 표본의 사후 원본 대조 및 저장된 후보 판정 재집계**다. 탐지율이 새 코드로 67.5%에서 79.4%로 향상된 실험이 아니다.

| 원본 대비 확인한 분류 | 파일 수 | 기존 후보 | 로컬 수정본 후보 | 수정본 후보 선정률 |
| --- | ---: | ---: | ---: | ---: |
| 순서표·switch 기반 평탄화 도입 | 11 | 9 | 11 | 100.0% |
| helper 연산·호출 우회 도입, switch 없음 | 23 | 16 | 16 | 69.6% |
| 표기 변화만 존재: 정규화 후 원본 AST와 동일 | 6 | 0 | 0 | 해당 변환 평가에서는 제외 |
| 전체 설정 그룹 | 40 | 25 | 27 | 67.5% |
| 표기 변화만 있는 6건 제외 | 34 | 25 | 27 | 79.4% |

기존 대비 같은 34건의 변화는 **25/34 = 73.5% → 27/34 = 79.4%**다. 순서표·switch 그룹은 **9/11 = 81.8% → 11/11 = 100%**다. 그룹 간 분모를 바꾼 수치를 코드 개선 폭으로 비교하지 않는다.

11/11은 이 사후 분류된 소규모 표본에서 난독화 후보로 선정됐다는 뜻이다. 모든 CFF 형태의 일반화 성능, CFF 기법 분류 정확도, 11파일 전부의 복원 성공률, 악성 탐지율을 뜻하지 않는다. 다른 난독화 신호를 통해 후보가 됐을 가능성도 있으므로 후보 선정 지표와 기법별 탐지 근거를 혼동하지 않는다.

## 2. 동일하게 적용한 검증 기준

40개 모두에 대해 원본 `.js`와 난독화본 `.obf.js`를 파싱했다. 성공한 27개를 건너뛰거나 실패한 파일만 대상으로 삼지 않았다. 검증 스크립트는 제품 detector 및 복원기 모듈을 import하지 않는다. 40개 분류가 끝난 뒤 저장된 후보 판정을 읽어 결합한다. 다만 분석자는 기존 결과를 알고 있었으므로 외부 블라인드 평가라고 표현하지 않는다.

### A. 표기 차이를 제외한 원본 구조 비교

제거·정규화한 항목:

- 위치 정보, 주석, 공백 및 파서의 원문 표기 메타데이터.
- 식별자로 표현 가능한 고정 문자열 속성 접근: `obj['prop']` ↔ `obj.prop`.
- 같은 값을 가진 숫자·문자열 리터럴의 raw 표기: `26` ↔ `0x1a`, `' '` ↔ `'\x20'`.
- 부수효과가 있는 원소가 없는 정확한 `!![]` 표현을 `true`로 정규화.

**문장 제거·재배열, helper 인라인, 분기 제거, 반복문 제거, 변수명 변경, 일반적인 상수 계산은 하지 않았다.** 비교는 JSON 문자열의 키 순서가 아니라 객체의 깊은 동등성으로 수행한다. 이 정규화 후 전체 Program AST가 동일하면 `SURFACE_ONLY`로 분류했다. 이는 문서화한 정규화 범위의 구조 비교이지 JavaScript 전체의 의미 동등성 증명은 아니다.

### B. 실제 도입된 순서표·switch 구조

원본에 switch가 없고 난독화본에 다음 구조가 새로 생겼는지 확인했다.

- 반복문 본문 안의 switch.
- 순서표를 증가 커서로 읽는 분기 선택식.
- 리터럴 배열 또는 문자열 split으로 추적 가능한 순서표. 지역 helper 객체의 문자열 속성도 추적.
- 순서표의 값이 case 집합의 순열이며 소스에 배치된 case 순서와 다름.
- 각 case의 끝이 continue 또는 return.

11파일에서 총 15개 switch가 이 구조로 확인됐다. 각 switch의 줄 번호·선택식·case 순서·순서표 값은 JSON에 보존했다. 이 검사는 표본의 구조를 분류하는 용도이며 임의 코드에 적용하는 안전한 복원 조건이나 제품 탐지기를 대체하지 않는다.

### C. helper 우회 구조

원본에 없던 지역 객체의 helper 함수가 난독화본에 추가되고, 동일 바인딩의 해당 속성을 호출하는 사용 지점이 있는지 확인했다. helper는 인자를 받아 이항·논리 연산을 하거나 다른 인자 함수를 호출하는 단일 반환문 형태다. 정의 위치·연산자·정의 코드·바인딩을 따른 호출 줄 번호를 기록했다.

23파일은 이 구조가 있지만 switch는 하나도 없었다. 따라서 `HELPER_ONLY`라고 구분했다. 이는 연산·호출 간접화가 도입됐다는 근거이지 기본 블록 순서를 switch로 평탄화했다는 근거가 아니다. 정상 유틸리티도 이 모양을 가질 수 있으며 여기서는 **원본 대비 새로 도입됐다는 정보**를 사용했다. 제품이 단일 파일만 보고 이 사실을 똑같이 알 수 있다는 뜻은 아니다.

나머지는 `UNRESOLVED`로 남기도록 했으며, 이번 40쌍에는 해당 분류가 없었다. 분류 가능한 구조를 찾았다는 것이 모든 변환과 의미를 완전히 검증했다는 뜻은 아니다.

## 5. 발표·보고용 권장 문구

> JsDeObsBench 기반 로컬 CFF 설정 그룹 40개를 원본과 대조했다. 표기 변화만 있는 6개를 제외하고, 순서표 기반 평탄화 또는 helper 우회가 확인된 34개 중 27개를 복원 후보로 선정했다(79.4%). 그중 순서표 기반 평탄화 11개는 모두 후보로 선정됐으며, 미선정 7개는 helper 우회 그룹에 속했다. 이는 기존 표본의 사후 분류 결과이며, 독립 평가셋의 일반화 성능이나 복원 성공률은 아니다.

짧은 수치 카드:

- **변환 확인 표본 후보 선정 27/34 (79.4%)** — 순서표 평탄화·helper 우회 포함, 표기 변화만 있는 6건 제외.
- **순서표 기반 평탄화 표본 후보 선정 11/11** — 사후 분류된 로컬 표본, 복원 성공률 아님.
- 각주: **전체 설정 그룹 27/40 (67.5%), 사후 원본 대조·저장 결과 재집계.**

피할 표현: “CFF 일반 탐지율 100%”, “복원 성공률 79.4%”, “코드 개선으로 67.5%→79.4%”, “데이터셋 오류 6건”, “정상 파일 6건 제거”.

## 6. 재현·검증·한계

- [최종 원본 대조 JSON](paired-source-audit.json): 40쌍 해시, 구조 증거, 후보 판정, 사용한 기존 결과 해시, 검증 스크립트 해시.
- [사용한 후보 판정](candidate-regression.json): 난독화본 40건의 SHA-256 일치를 모두 확인했다. 원본 해시는 이번에 기록했다. 공식 배포 아카이브와의 해시 일치까지 새로 확인한 것은 아니다.
- 검증 도구: `apps/scanner/scripts/tier2-cff-paired-audit.mjs` 및 `.spec.mjs`.
- 해당 도구의 회귀 테스트 **13/13 통과**. 값·문장 순서 변경, 부수효과 있는 배열 조건, 미사용 helper, shadowing, 기존 helper, 알 수 없는 순서표, 파싱 오류 등을 검사했다.
- 샘플 코드를 실행하거나 webcrack·GuardDog·Tier3를 실행하지 않았다. 제품 detector 코드·임계값·Gate·Policy는 이번 작업에서 변경하지 않았다.
- 기존에 관찰한 표본에 대한 사후 진단이다. helper 구조 정의와 dispatcher 정의는 이 보고서의 평가 하위 분류이며 팀의 제품 Contract나 외부 표준을 변경하지 않는다.
- 중간 산출물은 로컬에 보존하고, 이 디렉터리에는 순열 추적까지 확인한 최종 `paired-source-audit.json`만 포함했다. 두 실행의 분류·집계는 동일했다.
- 앞선 일회성 비교에서 JSON 키 순서 때문에 모두 불일치로 나온 중간 출력이 있었다. 객체 깊은 비교로 수정해 6건 동일성을 확인했고, 이번 재현 도구도 깊은 비교를 사용한다.

작업 트리의 `apps/scanner`에서 기존 설치 의존성과 Node 24를 사용한다:

```sh
node --test scripts/tier2-cff-paired-audit.spec.mjs
node scripts/tier2-cff-paired-audit.mjs <jsdeobs-sample 경로> <기존 complete.json 경로> <새 결과.json 경로>
```

출력 파일은 기존 파일이 있으면 실패하도록 생성한다. 이 문서는 #484 후속 PR에 포함한다. 평가 실행 당시에는 원격 작업을 수행하지 않았으며, PR 제출은 별도 후속 작업이다.
